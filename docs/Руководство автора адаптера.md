# Руководство автора адаптера

*[English](Adapter%20Author%20Guide.md) · Русский*

Как научить манипулятор Axel работать с объектами своего верстака: перемещать и поворачивать
их своим способом, масштабировать и выдавливать, объявлять точки редактирования и операции
двойными буквами. Публичный API — модуль `freecad.axel.api`, версия `API_VERSION = 1`
(раздел 16 спецификации). Всё остальное в пакете — внутреннее и может меняться.

Готовый пример — `freecad/axel/examples/cylinder.py`: адаптер `Part::Cylinder`, который
переводит масштаб в `Radius` и `Height`, выдавливание — в рост высоты или радиуса,
объявляет операцию-ползунок `A, A` для угла сектора и ограничивает намерение. Тесты к нему —
`freecad/axel/tests/test_scale_extrude.py`. Эталон операций над линиями —
`freecad/axel/adapters/draft.py` (`E, E` — выдавливание вершины, `D, D` — разбивка).

## 1. Как это работает

1. Пользователь выделяет объекты. Axel строит **цель** (`Target`) из элементов `TargetItem`:
   документ, путь выделения, перемещаемый объект по правилу 7.3 и его глобальная матрица.
2. Для каждого элемента реестр выбирает **адаптер**: первый по убыванию `priority`, у которого
   `supports(item)` истинно. Адаптеры верстаков регистрируются с `priority ≥ 100` и
   перекрывают стандартные (`placement`, `attachment`, `assembly`, `draft`).
3. Адаптер сообщает **возможности** (`capabilities`): какие ручки показать, на каких осях,
   можно ли копировать, почему объект недоступен.
4. Перетаскивание ручки — **сессия**: одна транзакция уровня приложения, отменяется одним
   Ctrl+Z. Axel считает **намерение** (`Intent`) в терминах рамки манипулятора — сдвиг,
   угол, коэффициенты, расстояние выдавливания, значение ползунка — и вызывает
   `begin → constrain → preview (много раз) → commit` или `cancel`.
5. Адаптер переводит намерение в изменения свойств. Ядро не знает типов объектов.

Правила, которые важно соблюдать:

- **Намерение всегда от начала сессии.** `preview` получает полный сдвиг / угол / коэффициент
  относительно снимка, сделанного в `begin`, а не приращение. Применяйте его к сохранённым
  исходным значениям, а не к текущим.
- **Ошибка не должна ронять FreeCAD.** Исключение в методе адаптера отменяет сессию с откатом
  и пишется в отчёт; но лучше не бросать исключений из `preview`.
- **Откат документа делает сессия.** `cancel` освобождает только то, что не относится к
  документу (временные узлы сцены, кеши).

## 2. Минимальный адаптер

```python
from freecad.axel import api

class PipeAdapter(api.Adapter):
    id = "mywb.pipe"
    priority = 100

    def supports(self, item):
        obj = item.object()
        return getattr(obj, "Proxy", None) is not None and getattr(obj.Proxy, "Type", "") == "Pipe"

    def capabilities(self, item):
        return api.Capabilities(
            handles=frozenset({api.HandleKind.MOVE_AXIS, api.HandleKind.ROTATE}),
            axes=frozenset({0}),        # только вдоль X рамки и вокруг него
        )

    def begin(self, items, intent):
        state = api.AdapterState(list(items))
        state.data["placements"] = {it.obj_name: it.object().Placement.copy() for it in items}
        return state

    def preview(self, state, intent):
        delta = intent.matrix()      # глобальная матрица D: G' = D·G
        for item in state.items:
            obj = item.object()
            original = state.data["placements"][obj.Name]
            # для объекта в контейнере: L' = P⁻¹·D·P·L, см. adapters/placement.py
            obj.Placement = App.Placement(delta * original.toMatrix())

    def commit(self, state, intent):
        self.preview(state, intent)
        return [item.obj_name for item in state.items]   # что пересчитать

api.register_adapter(PipeAdapter())
```

Регистрация — из `InitGui.py` верстака или при его активации. Верстак должен работать и без
Axel: оберните импорт в `try/except ImportError` и проверьте `api.API_VERSION`.

`Adapter` — обычный класс, наследование не обязательно, но удобно: методы по умолчанию
ничего не умеют. Часто проще наследовать стандартный `PlacementAdapter`
(`freecad.axel.adapters.placement`) и переопределить только то, что отличается, — так
сделаны `draft` и пример `cylinder`.

## 3. Протокол по методам

| Метод | Когда вызывается | Что вернуть |
|---|---|---|
| `supports(item)` | При каждой пересборке цели | `True`, если объект ваш |
| `capabilities(item)` | После выбора адаптера | `Capabilities`: ручки, оси, `can_copy`, `disabled_reason` |
| `frame_hint(item)` | При построении рамки | `FrameHint(origin, rotation)` или `None` |
| `edit_points(item)` | При одном выделенном объекте, после каждой фиксации | Список `EditPoint` с устойчивыми `id` |
| `operations(item)` | При пересборке цели | Список `OperationSpec` |
| `begin(items, intent)` | Нажатие на ручку | Непрозрачное состояние (`AdapterState`) со снимком |
| `constrain(state, intent)` | Перед каждым `preview` и `commit` | Намерение, возможно изменённое |
| `preview(state, intent)` | Каждое движение мыши | — |
| `commit(state, intent)` | Отпускание кнопки или Enter | Имена изменённых объектов |
| `cancel(state)` | Esc, удаление объекта, ошибка | — |
| `duplicate(state)` | `C, C` перед перетаскиванием | Новое состояние для копий |
| `operation_name(intent)` | Открытие сессии | Название для истории отмены |

### Возможности

- `handles` — типы ручек: `MOVE_AXIS`, `MOVE_PLANE`, `MOVE_FREE`, `ROTATE`, `SCALE_AXIS`,
  `EXTRUDE`. Ручки масштаба и выдавливания появляются **только** если адаптер их
  объявил: у объектов без адаптера их нет (решение 5 спецификации). `MENU` остался в
  перечислении ради совместимости, но ручки у него нет: меню открывается ПКМ по началу.
- `axes` — на каких осях рамки показывать стрелки, дуги, кубики, точки.
- `disabled_reason` — манипулятор показан серым, причина в подсказке и строке состояния.
  Используйте вместо `supports() → False`: пользователь должен понимать, почему нельзя.
- При нескольких объектах возможности пересекаются: показывается общий набор ручек.

### Рамка

`FrameHint.origin` задаёт начало манипулятора вместо центра габаритов (например, ось трубы),
`FrameHint.rotation` — ориентацию в режиме «По объекту» (например, X вдоль трубы). Если
элементов с подсказками несколько, начало — центр их габаритов.

## 4. Что приходит в намерении

`Intent.operation` и заполненные поля:

| Операция | Поля | Как применять |
|---|---|---|
| `TRANSLATE` | `translation` (глобально) | `intent.matrix()` — матрица `D` |
| `ROTATE` | `axis`, `angle` (радианы), `center` | `intent.matrix()` |
| `SCALE` | `factors` по осям **рамки**, `center`, `axis` | `intent.matrix()` даёт `T(c)·R·S(f)·R⁻¹·T(−c)`; параметрическому объекту чаще нужны сами коэффициенты — переведите оси рамки в оси объекта, как в `examples/cylinder.py` |
| `EXTRUDE` | `distance` (мм, со знаком), `axis`, `both_sides` | Геометрию строит адаптер; матрицы нет |
| `PARAMETER` | `value`, `op_id` | Ползунок операции; матрицы нет |

Общие поля: `frame` — рамка на начало сессии, `handle` — какая ручка, `copy` — идёт
копирование, `op_id` — взведённая операция, `point_id` — двигается точка редактирования,
`step` — действовал шаг, `source` — мышь или числовой ввод.

Что уже сделало ядро: сила перетаскивания, шаг (Ctrl), запрет отрицательного масштаба
(`AllowMirror`), экранный режим поворота, ограничение ползунка `minimum…maximum`. Адаптер
получает готовое значение.

`constrain` — место для своих ограничений: привязать длину к шагу сетки, запретить меньше
минимума, притянуть к точкам соединения. Верните `dataclasses.replace(intent, …)`.

## 5. Масштаб и выдавливание

Ручки масштаба (кубики на осях) и выдавливания (точки на стрелках) показываются, если
`capabilities` включает `SCALE_AXIS` и `EXTRUDE`. Модификаторы:

- масштаб: перетаскивание — по одной оси, Shift — равномерно по трём, Shift на Move 2D —
  по двум осям плоскости; щелчок по кубику — числовой ввод коэффициента;
- выдавливание: перетаскивание точки — `distance` вдоль оси, Shift — `both_sides`.

Смысл операций определяет адаптер: для трубы масштаб вдоль оси — изменение длины участка,
выдавливание — продление. `examples/cylinder.py` показывает, как учесть, что масштаб идёт
относительно начала манипулятора, а не начала объекта: основание сдвигается так, чтобы точка
`intent.center` осталась на месте.

## 6. Точки редактирования

`edit_points(item)` возвращает точки с устойчивыми `id`, глобальным положением и, при
необходимости, ориентацией и своим набором ручек. При одном выделенном объекте на нём
появляются маркеры; щелчок по маркеру ставит манипулятор в точку. Дальше сессия идёт как
обычно, но в намерении заполнен `point_id`: адаптер двигает эту точку, а не объект
(`adapters/draft.py`, вершины `Points`).

После фиксации адаптер снова опрашивается, выбранная точка сохраняется по `id`. Если
операция создала новую точку, которую нужно выбрать (как `E, E`), положите её `id` в
`state.select_point`.

## 7. Операции двойными буквами

```python
def operations(self, item):
    return [
        api.OperationSpec(
            id="length", scope=api.OperationScope.OBJECT, key="L", title="Set length",
            handles=frozenset({api.HandleKind.MOVE_AXIS}),
            param=api.ParamSpec(kind=float, default=float(item.object().Length),
                                minimum=10.0, maximum=5000.0, title="Length", step=50.0),
        ),
    ]
```

- Команда FreeCAD и сочетание `L, L` создаются **автоматически**, как только операция впервые
  появляется у цели; сочетание переназначается в «Инструменты → Настройка», пункт есть в
  меню манипулятора. Буквы C, E, D закреплены за копией, выдавливанием и разбивкой —
  адаптер, который реализует выдавливание или разбивку, объявляет операцию с `id="extrude"`
  / `"split"` и получает стандартные команды `Axel_OpExtrude` / `Axel_OpSplit`. Новая
  операция с занятой буквой не регистрируется, ошибка пишется в отчёт.
- `scope` — над объектом или над выбранной точкой. Операция для точки может ограничить, для
  каких точек она доступна: `points=frozenset({"v0", "v5"})`.
- `handles` — на каких ручках операция действует; на остальных перетаскивание обычное.
- Пользователь нажимает двойную букву, затем тянет ручку. В намерении приходит
  `op_id`; `begin` получает его уже при открытии сессии и может подготовить снимок иначе
  (как `draft` вставляет копию вершины для `extrude`).
- Операция с `param` — **ползунок**: намерение `PARAMETER` со значением, которое растёт при
  движении курсора вдоль экранного направления ручки, каждые `SliderStepPx` пикселей —
  `±1` для `int` или `±step` для `float` (по умолчанию `(maximum − minimum) / 100`). Цифры
  во время ползунка задают точное значение, отпускание применяет, Esc отменяет. Во время
  ползунка документ не меняйте: в `preview` заполните `state.markers` — Axel покажет
  маркеры будущего результата и подпись `«title: value»`; изменяйте документ в `commit`.

## 8. Копирование

`C, C` перед перетаскиванием вызывает `duplicate(state)` сразу после `begin`: создайте копии
(`doc.copyObject`), верните новое состояние для них; оригиналы верните к исходному
положению. Всё это внутри одной транзакции — Ctrl+Z удалит копии. После фиксации Axel
выделяет копии (имена из `commit`). Запретите копирование через `can_copy=False`.

## 9. События и подавление

```python
api.events.drag_started.connect(lambda target, intent: ...)
api.events.drag_committed.connect(lambda target, intent, changed_names: ...)
api.events.drag_cancelled.connect(lambda target: ...)
api.events.target_changed.connect(lambda target_or_none: ...)
api.events.operation_armed.connect(lambda op_id_or_none: ...)

api.add_suppression_rule("mywb.tool_active", lambda: MyTool.is_running())
api.remove_suppression_rule("mywb.tool_active")
api.current_target(), api.is_enabled(), api.refresh()
```

Обработчики вызываются в главном потоке; исключение логируется и не мешает Axel. Правило
подавления скрывает манипулятор, пока предикат истинен (например, идёт собственный
интерактивный инструмент верстака) — оно проверяется при каждой пересборке цели, при
добавлении и снятии правила цель перестраивается.

## 10. Типичные ошибки

- **Приращения вместо полного намерения.** `preview` вызывается многократно с полным
  значением от начала сессии; складывать его с текущим состоянием объекта нельзя.
- **Пересчёт в `preview`.** Не вызывайте `recompute` сами: политику пересчёта во время
  перетаскивания задаёт пользователь (`RecomputeDuringDrag`), после `commit` Axel
  пересчитает объекты, имена которых вы вернули.
- **Свои транзакции.** Не открывайте `doc.openTransaction` — сессия уже держит транзакцию
  уровня приложения; вложенная сломает отмену одним шагом.
- **Копии внутри контейнера.** `doc.copyObject` создаёт копию вне контейнеров; добавьте её
  в контейнер оригинала сами (см. `PlacementAdapter.duplicate`).
- **Габариты на каждый вызов.** `Shape.BoundBox` в FreeCAD 1.1 течёт по слабой ссылке на
  вызов; не считайте габариты в `preview` — кешируйте в `begin`.
- **Буква операции.** C, E, D заняты; одиночная буква, совпадающая с клавишей другой команды,
  не конфликт (двойная срабатывает сразу, одиночная — по таймауту), но точное совпадение
  `L, L` с чужой командой оставит операцию без сочетания — Axel напишет об этом в отчёт.
- **Регистрация до запуска Axel.** `api.register_adapter` можно вызывать в любой момент:
  если Axel ещё не включён, адаптер просто ждёт в реестре.
